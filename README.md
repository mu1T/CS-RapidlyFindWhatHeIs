# CS-RapidlyFindWhatHeIs

在 Steam 个人资料页（steamcommunity.com/id/*、/profiles/*）上叠加一个 CS2 成分查询面板：
把同一个人在各对战平台上的段位、评分、战绩与封禁标记，直接摊在资料页旁边。

版本：1.12.1（以同目录 manifest.json 的 version 为准）

这是**自动生成的「可外发档」源码副本**，不是作者的原始工程树。与原始代码相比：

· 注释按规则剥除，只保留第三方授权声明原文（见 qrcode-lite.js）。所以这里的代码能读、

  代码不存在不可逆保密，给足时间一定能还原。
· 代码里的内置隐私名单是**空数组**（F5E_CONTACT_DENY = []）。判定机制原样保留、开关照旧
  工作，只是不随本目录携带条目 —— 那是别人的真实姓名与账号标识，不该跟着一次「顺便开源」
  进公网仓库。

## 安装（加载已解压的扩展程序）

1. Chrome / Edge 地址栏打开 chrome://extensions（Edge 为 edge://extensions）
2. 打开右上角「开发者模式」
3. 点「加载已解压的扩展程序」，选择**本目录**（含 manifest.json 的那一层）
4. 打开任意一个 https://steamcommunity.com/profiles/… 或 /id/… 页面，面板自动出现在资料页
   上；设置入口在扩展图标 → 详情 → 扩展程序设置

## 隐私与数据流（如实描述）

· 不收集也不上传访问者的 Steam 凭据。但库存与市场请求带 credentials: 'include'，浏览器会把
  **用户自己的 steamcommunity.com Cookie** 随请求发给 steamcommunity.com —— 这是「读你自己
  能读到的页面」的必要条件，目标站点就是 Steam 本身。
· 第三方平台的身份是用户自备的 token（手填，或从该平台网页登录过程捕获），只存在本机
  chrome.storage.local，只回放给该平台自己的接口。
· 缓存全部落在 chrome.storage.local 的 sps_cache_* 键下；设置页提供「清全部」与「按平台清」。
· 为了对上平台自身的请求口径，扩展用 declarativeNetRequest 改写自己发出的请求的来源 /
  Referer 头。这一条请如实知悉：它会让请求在平台侧看起来像该平台网页发出的。
· 使用「完美 demo 直链」时会请求 api.ipify.org / ifconfig.me 读取你当前的**公网 IP** ——
  该平台的签名方案把 IP 算进签名里，所以这个值会随签名进入发往该平台的请求。除此之外不
· 对 csstats.gg 的直连请求过本地令牌桶限速（每分钟 20 个），撞上 Cloudflare 限流（429 / 1015）
  后整体静默退避（默认 10 分钟）—— 这是为了不把共享出口 IP 打进站点的限流名单，属于自我约束，
  不是数据收集。
  主动上报 IP。
· 被查询者的 SteamID / 昵称会出现在发往第三方平台的查询参数里（这就是查询的语义本身）。

## 使用风险与边界

· 上述平台接口多为私有接口，未公开承诺可供第三方调用。使用本扩展**可能违反相关平台的服务
  条款**，并可能触发风控或账号风险；由此产生的后果由使用者自行承担。
· 本项目不支持、不鼓励把代码改造成批量采集 / 轮询 / 绕风控的工具（LICENSE 附加条款 2）。
· 录像与第三方资源只给入口：插件把直链现算出来交给用户（左键复制 / Ctrl+左键自己打开），
  不代下载、不落盘。这个口子收窄到「用户自己的 token + 用户自己的比赛、一次一场、必须用户
  点击」，不做批量、不轮询、不后台预取。
· 口径红线：不同平台的评分永不相乘、永不加权成一个「总分」；缺数据一律显示不可比或隐藏，
  绝不填 0；第三方载荷里带着大量个人敏感字段，任何入库前都要先过白名单。

## 运行环境与构建（Node 部分）

先说结论：**使用本目录不需要安装任何东西**。扩展本体是原生 JavaScript，运行时零依赖 ——
chrome://extensions 加载即用，上一步就是全部。

Node 与 npm 只在两处出现：构建发布产物、跑测试与门禁。这两件事的完整工具链（测试、审计、
混淆、验证脚本）**有意不随本目录发布**，所以下面的命令都在主仓库运行 —— 在本目录里执行会
因为没有 package.json 而直接失败，这是设计而不是疏漏。
